### Introduction
A **Graphics Processing Unit (GPU)** is a processor whose design emphasizes performing *large amounts* of *parallel work*. GPUs began as specialized hardware for real-time graphics, then gained programmable graphics stages. **NVIDIA** introduced **CUDA in 2006 so programmers could use GPU throughput for general computation without expressing the work as graphics operations.

CUDA, originally expanded as Compute Unified Device Architecture, now names NVIDIA's broader heterogeneous-computing platform: its GPU programming models, software interfaces, compiler toolchain, libraries, and supporting hardware features. A GPU is the physical processor; CUDA is the platform through which software uses compatible NVIDIA GPUs.

> Although we focus primarily on CUDA in this course, GPU programming is broader than CUDA. Other vendors (AMD's HIP, Intel's SYCL, Apple's Metal) & Cross-Platform Interfaces (OpenCL, Vulkan Compute, OpenMP) exist.

#### What is a Processor Doing?
- The journey of any software starts at a human-written (or AI written nowadays, sigh) source code, which then a **compiler** translates into *lower-level representations* that a *target machine* / a later compiler stage can execute / translate further. 
- Post compilation much of the work is represented as **instructions**: basic core operations such as:
    - `load a value from memory` / `add two values` / `compare` / `branch` / `store a result`
  
  The values an instruction operates on are called its *data*.
- A **processor** then is the hardware that repeatedly obtains such instructions, determines what they mean, obtains their input data, performs the operation and records the result.
    - To make the process more efficient real world processors overlap these steps from multiple streams and may execute multiple operations at once.
    - An **instruction stream** is defined as the ordered sequence of instructions followed by one executing programming context.
    - An *instruction stream* combined with the execution context (registers / stack / program counter) is referred to as a **Thread**.
- CUDA threads tend to be much more lightweight and numerous than CPU threads, to unlock massive parallelism as we will shortly discuss.
